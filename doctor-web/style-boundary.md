# Style Boundary

## Purpose

本文件用于严格规定医生端 Web 的风格借鉴边界。

目标不是“多参考融合”，而是：

- 先划清来源
- 再限定模块
- 最后统一落地

后续任何设计改动，都必须先符合本文件，再进入实现。

---

## Scope

本文件适用于：

- 登录页
- 患者列表页
- 患者详情页
- 共享组件
- 后续新增的医生端 Web 页面

不适用于：

- 患者端 Uniapp
- 品牌宣传页
- 营销落地页

本项目的本地设计文档优先级高于外部参考源。

## Role Split

### IBM

`IBM` 只负责系统级视觉骨架。

允许负责：

- 颜色层级
- 字体层级
- 信息优先级
- 按钮语义
- 表格样式
- 表单控件
- 标签与状态色
- 边框与分隔线规则

不允许负责：

- 页面情绪感
- 内容区的柔和氛围
- 工作台布局编排

一句话：

`IBM` 管“系统语言”，不管“页面气质”。

### Intercom

`Intercom` 只负责舒适度与内容容器气质。

允许负责：

- 页面阅读舒适度
- 卡片内部留白
- 空状态区
- 说明区
- 提示区
- 辅助文案区
- 柔和的内容容器节奏

不允许负责：

- 主色体系
- 状态语义
- 表格规则
- 输入框规则
- 系统级按钮规则

一句话：

`Intercom` 管“舒适度”，不管“系统规范”。

### Airtable

`Airtable` 只负责工作台结构与信息编排。

允许负责：

- 页面级布局结构
- 列表区与详情区关系
- 工具栏结构
- 筛选区组织
- 面板分区节奏
- 工作流型信息编排

不允许负责：

- 颜色系统
- 卡片皮肤
- 表单视觉语言
- 按钮和 tag 样式

一句话：

`Airtable` 管“工作台结构”，不管“视觉皮肤”。

## Module Mapping

### Global Design Tokens

唯一来源：`IBM`

包括：

- 主色
- 中性色
- 状态色
- 文本颜色
- 边框颜色
- hover 颜色

禁止：

- 把 `Intercom` 或 `Airtable` 的颜色哲学混进全局 token

### Typography

唯一来源：`IBM`

包括：

- 标题层级
- 正文字号
- 信息主次
- 数据数字权重

禁止：

- 页面之间自行变更层级体系

### Buttons / Inputs / Tags / Tables

唯一来源：`IBM`

包括：

- 主按钮
- 次按钮
- 输入框
- 下拉框
- 标签
- 数据表格

原因：

- 这些属于系统级组件，必须统一，不允许多源。

### Content Cards

主来源：`IBM`

辅助来源：`Intercom`

允许：

- 用 `IBM` 定卡片边框、半径、层级
- 用 `Intercom` 调整卡片留白、阅读舒适度、辅助文案密度

禁止：

- 为了“更温和”改变卡片边框哲学
- 用 `Intercom` 替代 `IBM` 的组件规则

### Workspace Layout

唯一来源：`Airtable`

包括：

- 页面主布局
- 列表与详情布局关系
- 筛选工具栏位置
- 侧栏与主工作区关系
- 面板分组节奏

禁止：

- 一部分页面用工作台逻辑，另一部分页面切成展示型布局

### Empty States / Helper Blocks / Notes

主来源：`Intercom`

辅助约束：`IBM`

允许：

- 借 `Intercom` 做更温和的空态和说明块
- 继续服从 `IBM` 的颜色和层级系统

禁止：

- 做成营销页插画块
- 做成 AI 产品说明卡

### Charts

主来源：项目本地规则

辅助参考：`IBM`

包括：

- 图表颜色克制
- 坐标轴清晰
- 数据优先
- 交互轻量

禁止：

- 使用 `Airtable` 视觉皮肤控制图表
- 使用 `Intercom` 的柔和感削弱图表可读性
- 做成展示型炫技图表

## Page Mapping

### Login Page

主来源：`IBM`

辅助来源：`Intercom`

禁止引入：`Airtable`

说明：

- 登录页不是工作台，不需要复杂编排。
- 重点是可信、克制、清晰。

### Patients List Page

主来源：`Airtable`

系统组件来源：`IBM`

舒适度来源：`Intercom`

说明：

- 页面结构借 `Airtable`
- 列表卡片、表格、标签、按钮借 `IBM`
- 空态、辅助说明、轻提示借 `Intercom`

### Patient Detail Page

主来源：`Airtable`

系统组件来源：`IBM`

内容舒适度来源：`Intercom`

说明：

- 详情页最容易风格失控，必须按三层拆分。
- 结构归 `Airtable`
- 组件归 `IBM`
- 容器舒适度归 `Intercom`

---

## Anti Mixing Rules

以下情况一律禁止：

- 同一个按钮同时借两个参考源
- 同一张卡片既改边框哲学，又改布局哲学，又改颜色哲学
- 同一页面的不同区域使用不同颜色体系
- 把 `Intercom` 的柔和感扩散为全局组件规范
- 把 `Airtable` 的工作台结构误用为视觉皮肤
- 为了“更高级”引入额外第四套参考源

---

## Decision Order

新模块开始前，必须先回答：

1. 这是系统组件、内容容器，还是工作台布局？
2. 它的主参考源只能选一个，选谁？
3. 其他参考源是否只是辅助，而不是主导？

如果答不清，不允许直接开始设计。

---

## Execution Rules

后续任何新页面或新模块，执行顺序固定：

1. 先判断模块类型
2. 再根据本文件确定主来源
3. 再检查是否触犯禁混规则
4. 最后才进入实现

如果页面做坏了，不在页面内继续无边界试错。

正确做法是：

- 回到本文件重新确认归属
- 重新做最小范围修正
- 必要时回退到当前稳定基线，再重新推进

---

## Current Baseline

当前医生端 Web 的基线策略为：

- 基础视觉语言：`IBM`
- 阅读舒适度：`Intercom`
- 工作台布局结构：`Airtable`

后续只能在这个基线上细化，不再扩大参考源范围。
